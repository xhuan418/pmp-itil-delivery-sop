# 全生命周期项目与服务 SOP

本 SOP 将 PMP 的项目治理与 ITIL 4 的服务管理连接起来。按当前阶段选择所需动作和模板，不要求每个项目制作全部文档。

## 阶段 0：需求进入与分流

### 目标

确认这是什么工作、它创造什么价值、谁可以决定下一步。

### 要做的事

- 明确客户/用户要实现的结果、影响范围、紧急程度和约束。
- 分类：项目、服务请求、事件、问题、标准变更、正常变更、紧急变更或持续改进。
- 查询现有合同、服务目录、知识库、Backlog、项目计划和已知错误。
- 记录需求、假设、依赖、风险和待决策事项。

### 产出

- 一页需求进入记录：结果、范围边界、提出人、负责人、决策人、下一步。

## 阶段 1：立项与对齐

### 目标

在开始承诺前，确认项目为什么做、成功如何衡量、谁负责什么。

### 要做的事

- 确认业务目标、成功标准、范围边界、交付方式和关键约束。
- 明确发起人、客户/产品负责人、项目负责人、交付团队、受影响用户和审批人。
- 确认决策权、沟通节奏、里程碑预期和初始风险。
- 获得相应授权后，再将工作对外表示为已承诺。

### 产出

- 轻量项目章程或立项说明。

## 阶段 2：规划与设计

### 要做的事

- 根据不确定性、治理要求和发布节奏选择预测型、敏捷或混合模式。
- 拆分里程碑、Backlog 或工作包，并明确负责人和验收标准。
- 明确依赖、风险、质量检查、客户触点、沟通方式和升级路径。
- 只在相关方确认后建立范围、排期和资源承诺。
- 尽早规划服务就绪：支持、监控、知识、权限、培训、服务目标和回滚。

### 产出

- 交付计划/Backlog、风险清单、相关方与沟通安排、服务就绪计划。

## 阶段 3：交付与控制

### 每周或每迭代固定节奏

1. 确认已完成的工作和已交付的客户价值。
2. 重申下一阶段优先级和依赖。
3. 审查风险、问题、决策和变更。
4. 列出需要客户或管理层确认的事项。
5. 记录负责人、承诺和截止日期。

### 需要持续维护的记录

| 记录 | 用途 |
|---|---|
| 行动清单 | 工作、负责人、截止日期、状态、阻塞项 |
| 风险清单 | 未来不确定性、触发条件、预防/应急措施、责任人 |
| 问题/事件清单 | 当前影响、缓解措施、负责人、下一次更新时间 |
| 决策/变更记录 | 提出事项、影响、选项、决策人、日期与结果 |

## 阶段 4：变更、事件与问题处理

### 变更分流

| 场景 | 路由 |
|---|---|
| 可重复、低风险、预授权的操作 | 标准变更 |
| 有实质影响或风险的修改 | 评估影响、测试、审批、实施、验证、记录 |
| 为恢复/防止严重服务影响的紧急操作 | 紧急变更：快速授权、受控实施、事后复盘 |
| 敏捷中尚未承诺的需求或缺陷 | 进入 Backlog，由 PO 排序 |
| 影响受治理范围、基准或对外承诺 | 正式评估影响并取得相应授权 |

### 事件与问题分流

| 场景 | 第一目标 | 后续动作 |
|---|---|---|
| 服务中断或性能下降 | 恢复服务并沟通 | 记录、分类、确认恢复 |
| 反复或重大事件 | 控制影响 | 问题记录、根因分析、已知错误/绕过方案、永久修复 |
| 预定义的用户需求 | 稳定地完成请求 | 从服务目录交付 |

## 阶段 5：上线与服务交接

部署并不等于完成。上线前或上线时确认：

- 已指定服务负责人及支持/升级路径。
- 已明确支持时间、优先级、客户联系渠道。
- 监控、告警、权限、备份和安全需求已确认。
- 知识库、运行手册和已知绕过方案已可用。
- 用户和支持团队已完成必要培训。
- 发布、验证与回滚计划已确认。
- 服务目标和报告节奏已达成一致。
- 未关闭风险/问题已有交接负责人和日期。

## 阶段 6：收尾与持续改进

- 取得交付物验收，确认责任完成移交。
- 关闭合同、权限、临时资源和项目行动项。
- 趁证据新鲜记录经验：发生了什么、产生什么影响、下次如何做得更好。
- 将重复运营痛点转为可衡量的持续改进项。
- 回看客户/业务结果和服务指标是否真正实现。
